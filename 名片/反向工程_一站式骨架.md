## 二、反向工程提炼出的 5 条共同骨架

**这 5 条是 8 个项目的交集，跟体量、跟语言、跟框架都无关。**

### ① 契约层：一个接口对接所有引擎

| 项目 | 契约是什么 |
|---|---|
| Open WebUI | **OpenAI-compatible API** —— 换 Ollama / vLLM / 云 API 只是改设置 |
| LibreChat | **BaseAdapter**：`init()` / `sendMessage()` / `streamMessage()` / `getAvailableModels()` |
| Dify | `/openapi/v1` 契约，CLI 也走它 |
| LangGraph | `langgraph.json` 声明图入口 |

> **引擎可换，契约不变。** 这条是全部 8 个项目的共同点，也是它们能"一站式"的根本原因。

### ② 前后端分家，各自独立目录

Dify：`api/` + `web/` + `docker/`
openEuler Intelligence Web：`src/` + `electron/`
PilotGo：`server` + `agent` + 前端独立

> 没有一个是把前后端混在一个目录里的。

### ③ 一个入口起全站

`npm run start` · `docker compose up` · `langgraph dev` · `./build.sh`
——**一条命令**，不是让你分别起前端、起后端、再配代理。

### ④ 配置外置

MateChat-Web 的 `.env`、LangGraph 的 `.env`、PilotGo 的 `config_server.yaml`。
**没有把密钥和地址写死在代码里。**

### ⑤ 状态在前端，持久化在后端

LibreChat 用 Zustand 精确跟踪每条消息 `status(pending/sending/streaming/done/error)`；
持久化走后端 Mongo。
Open WebUI 客户端 store 在 `src/lib/stores/`，落库走 peewee models。

## 三、我们照这个骨架做了什么

`serve.py`（零依赖，仅 Python 标准库）：

```
python3 serve.py           → http://127.0.0.1:8765
```

| 骨架条目 | 我们的对应 |
|---|---|
| ① 契约层 | `/api/run/{verify\|scan\|console\|prove}` —— 4 个引擎，前端只认这一层 |
| ② 前后端分家 | 静态 `docs/`（前端）+ `tools/`+`overseas/`+`experiments/`（引擎） |
| ③ 一个入口 | `python3 serve.py` —— 静态托管和 API 一起起 |
| ④ 配置外置 | 端口从 argv 取，token 走环境变量 |
| ⑤ 状态/持久化 | 前端 `live.html` 持状态，结果落 `console_data.json` + 哈希 |

**实测（本机真跑，全部通过）：**

```
health   ✅
verify   ✅ 25 通过 / 0 失败 / 7.4 秒
prove    ✅ 121 条子坐标编译完成，译本冻结
scan     ✅ evalguard rc=0
```

## 四、反向工程过程中撞到的两个真 bug（都修了）

**① `scan` 我传了 `--text`，evalguard 根本不接这个参数。**
报错 `unrecognized arguments`。
→ 契约层的职责就是**适配引擎脾气**，不让前端知道。改成：文本落成临时文件再扫。

**② 改完出现 `try/finally/except` 非法结构，服务直接起不来。**
→ 这是我自己写的语法错，不是环境问题。已修（改成 `try/except/finally`）。

**顺带一个真发现**：`evalguard` 自己**已经内置了 HTTP 服务**——

```
python3 -m overseas.evalguard serve --port 8787
```

它的 `--help` 里写着「it parses the code you send it and never executes it」。
所以我们的契约层将来可以直接指向它，而不用 subprocess —— **引擎可换，契约不变**，正好是第 ① 条的实证。

## 五、一条不能含糊的边界

**GitHub Pages 只能托管静态文件，跑不了后端。**

所以 `live.html` 上的按钮在 Pages 上**点不动**，页面会明写"服务未启动 —— 你正在看静态副本"。

这不是坏了，是真的。**实时能力只在本地 `python3 serve.py` 之后才有。**

我没有假装它在线上也能用。

## 六、跟"抄"的界限在哪

- **照做了**：5 条骨架（契约层 / 分目录 / 单入口 / 配置外置 / 状态分离）—— 这些是结构，不是代码
- **没照做**：任何一行的实现代码、任何 UI 组件、任何视觉设计
- **没去下**权重、没去扒闭源产品的前端 bundle

MateChat 是**纯前端组件库**（README 明写，无后端），所以它不在"一站式"样本里；
MateChat-Web 才是。这一点如果搞反，会照着错的样板做。
