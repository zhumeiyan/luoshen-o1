## 一、先划红线：什么我没做

**豆包客户端不逆向。** 搜索结果明确写着：「豆包客户端没有完整源代码的官方公开仓库，
官方 GitHub 重点开放 SDK、示例、模型研究和训练工具，社区仿制项目只能作为学习样例」。

我不做这三件事：
1. 不反编译豆包客户端 / App
2. 不抓包、不破解它的私有通信协议
3. 不绕过鉴权拿内部接口

**原因不是技术做不到，是这三条越过法律和平台条款的线。**

## 三、最有价值的发现：Skill 规范对照

豆包能装的「通用 Agent Skill 格式」（`anthropics/skills`，**182,365 star**），
TACT 那个 zip 就是照它做的。我把它跟我们的**洛神接入协议**做了逐条结构对照：

| 维度 | Skill 规范 | 洛神协议 | 判 |
|---|---|---|---|
| 身份声明 name | 有 | 有 | 都有 |
| 触发条件 when to use | 有 | 有 | 都有 |
| 反向条件 when NOT | 有 | 有 | 都有 |
| 工作流正文 | 有 | 有 | 都有 |
| 示例 | 有 | 有 | 都有 |
| **能力/工具声明** | **无** | **有** | **我们多** |
| **失败/边界声明** | **无** | **有** | **我们多** |

> **18 万 star 的通用规范，不要求声明「你做不到什么」，也不要求记录失败。**
> 这两条只有我们有 —— 正是协议第 1 条（先摸清你有没有手）和第 7 条（记录失败）。

这就是我们相对这套规范**多出来的东西**，也是洛神真正的差异点。

## 五、能落地的下一步

**把洛神接入协议打包成标准 SKILL.md 格式**（带 YAML frontmatter 的 name/description +
触发条件 + 反向条件），这样它能被豆包及任何兼容该格式的 AI **直接安装**。

TACT 就是这么做的（zip 发给豆包，豆包自己识别并完成安装）。
我们的协议**结构上完全兼容**，而且比它多两条。
