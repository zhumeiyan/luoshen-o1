# 客户端 ↔ 常驻接收端 · 修正版（2026-10-20）

## 一、上一版我错在哪

我声称"接上了"，其实**接收端建在了会死的东西上**：

| 我说的 | 实际 |
|---|---|
| 有客户端 | 是给人敲的 CLI，**不是 AI 用的** |
| 有接收端 | 是个**进程**，每轮临时拉起、测完就关 → **时间轴上不存在** |
| 接 Skill | 验证了结构（14文件/2个SKILL.md），**一次没执行它的判据** |
| 接 API | 只调了公开只读，**没测过带鉴权** |
| 线上 | Pages 静态托管，**线上没有接收端** |

## 二、根修：接收端从"进程"换成"仓库"

**进程会死，仓库不会。**

```bash
python3 client.py 投递 '{"text":"随便什么"}'   # 任何能发 HTTP 的 AI 都能投
python3 client.py 收件 remote                  # 读常驻收件箱
```

实测：

```
投递①  ok=true  落点 接收/inbox/20261020-183333-260574.json  sha=8d62b458f10ca673
投递②  ok=true  from=doubao                                   sha=dce25545a9ed0628
收件   总数=2  两条 payload 原样读回
```

**服务端进程死了，东西还在。** 这才是"发的时候有地方接收"。

## 三、连撞三个真 bug（都是真跑才撞出来的）

1. **`elif` 锚点对不上** —— `ping` 是首分支用的 `if`，替换静默失败，命令根本没注册
2. **URL 中文路径没百分号编码** —— `接收/inbox/...` 直接 UnicodeEncodeError
3. **serve.py 同一个编码问题**

修完才通。**这三个正好证明"装了不等于能用"。**

## 五、API 那格：一条诚实的否定

```
无鉴权 /user        → rc=401（真响应，接口通）
带鉴权 PUT 写入     → rc=401（写不进去）
```

**api 引擎做不了带鉴权调用——它不带凭据。**

但这不是缺陷，**是正确架构**：凭据该在客户端，不在服务端。
带鉴权的写入走 `投递`：客户端自带 token，实测成功。

| 通道 | 能力 | 凭据在哪 |
|---|---|---|
| `api` | 无鉴权只读 | 服务端不带 |
| `投递` | 带鉴权写入 | **客户端自带** |

## 六、抓取那格（如实）

```
www.qq.com         ✅ 133,332 字节
api.github.com     ✅ 2,262 字节
example.com        ❌ rc=403
gitee.com          ❌ rc=403
```

403 是沙盒出口策略（直连 urllib 同样 403），**不是代码问题**。**引擎本身通，半数的域名被拦。**

GitHub Pages 是静态托管，收不了东西。**这条我没解决，也不是靠我努力能解决的**——需要一台真服务器。

本地 → `python3 serve.py`；跨会话持久 → `client.py 投递`。
