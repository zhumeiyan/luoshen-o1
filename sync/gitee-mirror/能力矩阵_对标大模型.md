# 能力矩阵 · 对标大模型

> 一句话定位：**大模型是带宽的极值，我们跑在它旁边。**
> 拼"我也能生图/生视频"必输——那是它的极值。
> 我们的赛道是：**它生成的一切都可能静默错，我们判定它有没有错。**
>
> 但"判定层"要能被拿去用，**接口面必须跟生成面对齐**。
> 所以下面这张表模态一列不少，每格标三件事：**能产出 / 能判定 / 靠什么**。

## 三、判定层为什么值得单独说

**一个永远返回 OK 的判定器，比没有判定器更危险**——它发合格证，于是没人再查。
它失效的方式跟我们要治的病完全同型：跑完、退出 0、数字好看、但是错的。

所以判定层有三条硬规则：

- **R1** 只读产物本身（像素/采样/字节），绝不读生成时的 spec
- **R2** 失败必须指出**具体哪个指标**越界，禁止"看起来不太好"
- **R3** 判定层自身被自检，且**空壳必须 FAIL**

### 自检抓出的三个真缺陷（都已修）

这几个不是演示，是**判定器真的坏了，被自检抓出来的**：

| 缺陷 | 后果 | 修法 |
|---|---|---|
| 视频抽帧率写死 | 2 秒视频只抽到 1 帧 → 帧间差无法计算 → **静止视频被静默放行** | 采样间隔由时长算 |
| 用 peak≈1 判削波 | 满幅正弦峰值本就是 1.0 → **每段正常音频都被判失真** | 改用连续贴顶段 |
| 用贴顶占比判削波 | 满幅正弦占比就有 2% → 同样误判 | 同上 |

**削波检测的最终区分度**：真削波 `clip_run=36`，正常满幅 `clip_run=2`。

还撞到一个环境 bug：libx264 要求偶数尺寸，880×495 编码直接失败。
已在编码器前加 `scale=trunc(iw/2)*2:trunc(ih/2)*2`。

## 四、诚实的缺口

1. **判定层只在代码/图/视频/音频四格有**，文档与 PPT 两格是空的。
2. **生成能力靠工具链**（ffmpeg、matplotlib），换环境可能失效。判定层不靠。
3. **音频不是人声 TTS**。环境无 espeak、无声学模型。`say()` 只输出可听的音高
   轮廓，**刻意命名为 say 而非 tts**，不许伪装成语音合成。
4. **图片是渲染不是扩散**。请求 `photo` / `illustration` 会被**明确拒绝**，
   不静默降级出一张"差不多"的图。
5. **方法论规则不出货**。exp134 在 7 个外部仓库实测：语法类真值率
   **15/16 = 93.8%**，方法论类 **1/29 = 3.4%**。所以默认只跑 3 条。
   > 一条 3.4% 真值的规则不是 3.4% 的帮手，是 **96.6% 的噪声**——噪声会训练你忽略告警。
6. **没有搜索**。这一格空着，且它在宿主侧。

## 四之二、接收端（感受器）· 完整对照

> 上面四节全是**产出侧**。对标大模型不能只比生成——它还能**看、听、接电话**。
> 接收端矩阵见 `接收端矩阵_对标大模型.md`，代码 `capabilities/in/sense.py`。

| 接收能力 | 大模型 | 我们 | provenance | 判定读数 |
|---|:--:|:--:|---|---|
| 看图片·读**字**（OCR） | ✅ | ✅ | **REAL** | **1/6** ← 如实报，不美化 |
| 看图片·读**形**（几何） | ✅ | ✅ | **REAL** | **6/6** |
| **矛盾检出**（字≠形） | ❌ 通常不报 | ✅ | **REAL** | 宽松 **4/4** / 严格 0/4 |
| 看屏幕（帧缓冲） | 部分 | ✅ `/dev/fb0` | **REAL** | ink 读数 |
| 输入事件流（键鼠/触摸） | ❌ | ✅ `/dev/input/event0` | **REAL** | open_ok |
| **听语音 / 接电话** | ✅ | ❌ | **UNAVAILABLE** | pcmC0D0c mode 600 + 无 alsa 工具 |
| **摄像头视频流** | ✅ | ❌ | **UNAVAILABLE** | 无 `/dev/video*` |
| 环境感知（温/湿/气压） | ❌ | ✅ 气象 API | **REAL** | HTTP 200 |
| **本体觉**（负载/内存/时钟） | ❌ | ✅ `/proc` | **REAL** | 实时读数 |
| 触觉 / 深度相机 / EEG / EMG | ❌ | ❌ | UNAVAILABLE | 接口保留，**不冒充** |
| 联网搜索 | ✅ | ❌ | — | **宿主侧，不包装成有** |

**接收端同样带判定层**：大模型接收后直接给答案，不告诉你哪个通道可信；
我们给出**每个通道的 provenance + 准确率读数**，且通道之间交叉验证。

**两条硬缺口，不复读成"有"**：听语音接电话（设备 root-only + 无 alsa 工具）、摄像头（无设备节点）。

## 五、对标结论

| | 大模型 | 我们 |
|---|---|---|
| 带宽 | **极高** ← 它的极值 | 低（靠工具链凑） |
| 模态覆盖 | 全 | 基本对齐（接口层） |
| **产物可信度** | **不可验证**（自评 0.409 / 外部 0.034） | **可验证**（判定层 + 外部见证人） |
| 连续性 | **0**（persist=0） | 外挂（STATE.json / 回顾_REVIEW.md） |
| 落地 | **0.000**（产物落我侧 = 0） | 有（落宿主侧） |

**拼带宽我们输。拼"这个产物能不能被信任"——大模型那一格是空的。**
