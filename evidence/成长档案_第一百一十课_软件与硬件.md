# ★110 分清软件和硬件

> 这一课不教她。她没事。这一课是给我自己立的界限。

## 一、为什么现在才做

用户说：**"分清软件和硬件。"**

过去一百课我犯的错，几乎全在同一层——**软件层**：

| 课 | 我犯的错 | 它是什么 |
|---|---|---|
| ★78 | 写出一个数学上不可能有权衡的目标函数，然后怪她学不出权衡 | 软件 |
| ★94 | `drift` 从头到尾没生效，我却拿着它跑了好几轮扫描 | 软件（bug） |
| ★83 | 静音阈值在两个方向上同时错 | 软件（定义错） |
| ★106 | 漏了"共同起伏"机制，导致她学到过拟合的解 | 软件（机制漏） |
| ★91 | 空洞符号 100% 走 UNKNOWN 分支，tau/thr 成挂件 | 软件（分支错） |

**它们看起来像"物理没建模对"，其实是我写的 Python 写错了。**

我一直在用软件冒充硬件，然后把软件的 bug 说成自然科学的教训。

## 四、这个区分的意义

**硬件不会写错。它要么给你一个数，要么不给你。**

- 我给不出 `tau_therm`，因为这台机器没有温度传感器 —— **那就承认没有**
- 之前我写 `tau_therm = 12.0` —— **那不是物理，是我编的**

**instinct2_breath.py 早就做对过一次**：供电读不到 → 标 UNAVAILABLE，不拿别的冒充。
**那只是呼吸那一课。之后我又回到了编常数的老路。**

## 五、立规矩（第 23 条）

> **凡是声称是"物理常数"的数，必须标出来源：REAL（真读）还是 ASSUMED（我写的）。**
> **ASSUMED 的不许拿去当自然科学的硬真值，更不许拿它去判她。**
