# 洛神总仓

多 AI 推演的收纳与分诊结构。**不解决"谁对"，只解决"东西放哪、缺什么一眼可见"。**

## 你的动作只有一个

把 AI 给你的成品贴给我（或丢进 `01_原始投放/`），我负责套模板、归档、重生成索引。
**你不需要手动搬运，也不需要记住搬了什么。**

## 目录

| 目录 | 放什么 | 谁能改 |
|---|---|---|
| `00_核/` | 判据核、失败模式库 | **只有你** |
| `01_原始投放/` | 所有 AI 原始产出（inbox，只进不出） | 我 |
| `02_分诊/` | 自动分诊：事实 / 解释 / 决策 | 自动生成 |
| `03_证据/` | A 类（有代码可复现） | 自动生成 |
| `04_待补/` | B/C 类（无代码 / 复现不出） | 自动生成 |
| `05_索引/` | 有什么 / 缺什么 | 自动生成 |
| `tools/` | 投递模板 + 收纳脚本 | 我 |

## 用法

```bash
python3 tools/收纳.py            # 归档 + 重生成索引
python3 tools/收纳.py --check    # 只校验不移动
```

每次收纳后看 `05_索引/缺什么.md`。

## 三条硬规则

1. **判据核不可改。** 提交头 `改核` 字段非"否"则一票否决（已实测拦截）
2. **解释层多版本并存。** 分歧不许合并成共识文档，否则下个 AI 会当既成事实接着推
3. **AI 不互读全量。** 全知通道会让分化塌成 0（λ 放大 8 倍也救不回）

## 为什么这样设计

- git 天然满足 S1（commit 哈希链 append-only）
- 你 merge 的动作就是 S5（外部见证人）
- 缺 S2/S3 需人工补，不假装已有
