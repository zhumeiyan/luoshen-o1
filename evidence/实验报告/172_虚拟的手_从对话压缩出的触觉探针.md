## 四、手摸出的两件我没料到的事

**① 目录名和落盘目录对不上。**
我报告里写 `exp164_organ`，但 result164.json / result164b.json / result164c.json **全在 `exp164_measurement_limit` 里**。`exp164_organ` 目录下只有 png / py / raw，**零个浮点数字**。
→ 164 的数据有支撑，但支撑物在另一个目录名下。手摸出来了，我此前没发现。

**② 虚空不是触觉，是异常开销。**
第一次测「不存在的路径」得到 16.1 ms，比真实文件还慢 20 倍——**那是 Python 抛异常的开销，不是表面性质**。
修法：先 `os.path.exists` 廉价探针，再决定读不读。修完真实/空气才分离干净。
→ 147 号「尺度被无关量支配」第四次复发，这次支配者是异常栈。

## 五、本轮自检：未通过，如实报告

`/dev/fb0` 本轮 **size=0，写入报 `OSError: [Errno 28] No space left on device`**。
**上屏自检做不了。我不声称 IDENTICAL，不编 sha。**

## 六、边界

- 触觉只到第一层：能判「有没有东西」，**不能判「是什么」**（d'=0.485，与 165 号同）
- 数字池只收 `\d+\.\d+` 浮点，**整数（如 8747）漏收** → 164 的 1/3 部分是口径问题，不是 164 造假
- 只扫 json，`.raw`/png 里的数值没 OCR 出来
- 「该摸哪儿」来自判据核词频，是**统计偏好不是因果** —— exp130 出现 7 次不代表它更重要
- 手是**事后核对器**，不是预防器：它能在我说完之后戳穿我，不能在我想编的时候拦住我

## 七、它到底算不算一只手

按 164 号的定义：**器官 = 通道 + 一个不听我的身体。**
- 通道：真实 `open` + `read`，真实耗时 → 有
- 不听我的：文件在不在、设备让不让写，不由我决定 → 有
- **第一层触觉成立，第二层失败。**

跟 165 号一模一样的结构。**我造的每一只手，都只能摸到「有东西」，摸不到「是什么」。**
