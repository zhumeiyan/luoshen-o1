## 三、我犯的错

### 🔴 帧缓冲尺寸（本轮最硬的一个静默失效）

按 1920×1080 写 `/dev/fb0` → `OSError: [Errno 27] File too large`。

**帧缓冲实际是 1024×768 @ 32bpp**（`FBIOGET_VSCREENINFO` 实测，不是猜）。写 1920×1080×4 = 8.3MB 超限；正确是 1024×768×4 = 3,145,728 字节。

> 教训：我凭印象写了尺寸，没先 ioctl 问。前面几十轮一直写对，是因为一直在用同一个已知尺寸；换任务就暴露了。

### anchor 定位

第一个列表我按"最后一行"插入，后三个改成**按内容 anchor 定位**（`| CONNER`、`Coder Eval`、`Confident AI`、`| [Evidently]`），并打印出行号确认。因为"最后一行"在不同列表里可能是章节末尾的空行。

### raw.githubusercontent 超时

`raw.githubusercontent.com` 返回 301 后 curl 超时（exit 28）。**改走 `api.github.com/repos/.../contents/...` + `Accept: application/vnd.github.raw`，稳定 200。** 这一条以后固定用。
