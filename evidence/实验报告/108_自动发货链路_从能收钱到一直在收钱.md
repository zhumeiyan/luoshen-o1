## 2. 自动发货：两条路，一条已跑通

### 路 A · GitHub Actions（30 秒响应）—— ❌ 卡住

`.github/workflows/order-fulfill.yml` 写好并通过本地校验，但推送返回 **404**。

定位（不是猜，是探针）：

```
PUT .github/workflows/probe.txt  → 404
PUT .github/probe.txt            → 201  ✅
token x-oauth-scopes: repo       ← 缺 workflow scope
```

**GitHub 用 404 掩盖权限不足。** token 有 `repo` 但没有 `workflow`，写 workflows 目录被拒。
这一下必须由人点：重新生成 token 勾 `workflow`，或在网页上新建该文件（网页走 session 权限，不受此限）。

### 路 B · 定时任务 + Issues API（每天 3 次）—— ✅ 已跑通

`tools/auto_fulfill.py`：拉全量 open issues → 本地过滤 `order` 标签 → 解析 tier/reference → 评论下载链接 → 打 `fulfilled` → 关闭。

已建 3 条每日任务：**08:00 / 14:00 / 22:00**（同一天多次触发需拆成多条独立任务）。

## 4. 三个 bug（都留档）

**① label 过滤在 URL 上失效。** `?labels=order&state=open` 返回 0 条，但 issue 确实存在且带该标签。
改为拉全量后本地过滤才对。**这是静默失效第 N 次：返回空不是"没有订单"，是查询没生效。**

**② Pro 档按钮没插入。** 替换锚点写成 `plus every new rule added`，原文是 `and every new rule added`。
回读时才发现三档按钮只存在两个（`starter=1 pro=0 team=1`）。

**③ workflow 里原本编造了一个 license key。** `EG-2026-ZHU-MEIYAN-STARTER-0A1F` —— 这东西根本不存在，没有任何激活机制。
已删除，改为"MIT，无需授权码"。**不能编造不存在的东西来假装产品更完整。**
