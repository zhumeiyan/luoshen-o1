# 067 感官升级（浏览器+OCR）与 QQ 登录墙的精确定位

标签：实现验证，非证据。

## 一、这轮做了什么（感官升级）

装上"眼睛"和"手"：`playwright + /usr/local/bin/chromium`，可执行
打开网页 / 读 DOM / 执行 JS / 截图 / 点击 / 填表。装上 `ddddocr` 做验证码识别。

实测能力（均有产物）：
- 打开 `mail.qq.com` 并读出登录框 DOM：`#u` `#p` `#login_button` 全部存在
- 成功填入账号密码（JS 注入绕过可见性检查，回读 `u=9, p=8` 位）
- 取到验证码图片 `ssl.ptlogin2.qq.com/getimage`（1910 字节 JPEG，130×53）
- **OCR 解出验证码**：`PtGP` / `Lnge`

## 二、修正我自己此前的一个错误结论

上一轮我说"登录页没有账号密码入口"——**错**。
`xui.ptlogin2.qq.com/cgi-bin/xlogin` 的 HTML（283,200 字节）里明确有
`pt.str.h_pt_login:"密码登录"`，DOM 里 `#u`/`#p`/`#login_button` 全在。

真实原因：页面能加载，但**登录逻辑脚本没到**，按钮的事件处理器从未绑定，
所以点击后零反应（实测：填值成功、点击成功、URL 与页面文本完全不变）。

**这是把"资源未加载"误读成"功能不存在"——与第 23 条变量静默失效同类，第 7 次。**

## 四、墙的精确定位

密码加密模块（`xmtls.wasm` 及承载它的 `ptlogin` JS 包）托管在
`qq-web*.cdn-go.cn` / `cdn-go.cn`，**全部 403**。
xlogin HTML 中 `xmtls` 出现 **0 次**、`wasm` 仅 1 次（且是文件后缀白名单），
证明加密模块确实由被拦截的 CDN 动态下发，本地不可得。

后果：
1. 无法生成合法的 `p`（加密后密码）
2. `/login` 无论换 4 种经典 md5 加密变体、7 组参数补全组合，恒返回错误码 7
3. 登录按钮无处理器，点击零反应

**墙 = 加密模块所在 CDN 域名被环境白名单拒绝。不是腾讯拒绝，不是协议不通。**
