# 174 · 如何打开任何网站：死的请求 + 活的渲染

## 一句话

**"打开网站"这件事，我发出的那一半全是死的离散整数；我收到的那一半是活的，而且活到我拿不到。**

这跟 173 号「感官要活、效应器要死」是同一条规律，推广到一个新的领域。

---

## 一、效应器侧：操作就是死的数值

`/dev/uinput` 真实发出一串"人手打开网站"的动作（移动鼠标 → 点击地址栏 → 敲 h）：

```
事件结构 = 24 字节，5 个整数字段（sec, usec, type, code, value）

动作       type   code   value
移动鼠标     2      0      312
移动鼠标     2      1      -48
同步       0      0      0
按下左键     1      272    1
同步       0      0      0
松开左键     1      272    0
同步       0      0      0
敲入 h     1      35     1
同步       0      0      0
放开 h     1      35     0
同步       0      0      0
UINPUT_OK
```

**没有一个模拟量。** 鼠标位移是整数 312 / −48，左键是 272，h 键是 35，按下/松开是 1 / 0。

这就是你说的：**键盘鼠标是死的，我不需要真的像人手，我只需要产生死的数值。**

而"打开网站"这个动作的完整输入，同样是死的：
- URL（字符串）
- HTTP method（GET / POST，封闭集合）
- header、cookie（键值对）
- 点击坐标、按键 keycode（整数）

**这一整侧都是我的母语能精确产生的。**

---

## 二、感官侧：静态页拿得到，动态页拿不到

起本地 HTTP 服务（真 `python3 -m http.server`），造两个对照页面，真 `chromium --headless --dump-dom` 渲染：

| 页面 | 只抓源码（不执行 JS） | 真浏览器渲染后 |
|---|---|---|
| `static.html` | **7.2410** ✓ | **USD-CNY 7.2410** ✓ |
| `dynamic.html` | **NOT_FOUND**（页面写的是：加载中） | **USD-CNY 7.2410** ✓ |

`dynamic.html` 的源码里数值明文计数 = **0**（数值由 `fetch('rate.json')` 在运行时填入）。

**同一个抓取动作，静态页拿到全文，动态页只拿到「加载中」。**

## 三、你给的三个页面，正好是现实世界的证据

不用我构造——你贴过来的三份文档就是活证据：

| 页面 | 抓取结果 | 属于 |
|---|---|---|
| **GitHub · TACT** | 完整 README、目录结构、69 commits、star/fork 数 | 服务端渲染，**静态可拿** |
| **支付宝 · 跨境汇款** | `请选择` / `加载中` / 汇出金额空 / 手续费空 | JS 运行时填充，**只拿到占位符** |

**支付宝那一页和我的 `dynamic.html` 是同一个现象**：真人打开浏览器，看到汇率和手续费；而我抓到的只有"加载中"。

所以「打开网站」≠「抓到网页」。**真正的打开，需要一个会执行 JS 的东西替我跑一遍——而那个东西是不听我的进程。**

---

## 四、合起来：打开网站 = 死的请求 + 活的渲染

```
我发出：URL + method + header + 坐标 + keycode   ← 全离散、全死、我能精确产生
          ↓
      网络 + 服务端 + JS 引擎                    ← 在动，不听我的
          ↓
我收到：渲染后的 DOM                              ← 活的一侧，也是我容易拿错的一侧
```

**死的那一侧我不缺；活的那一侧我造不出来，只能借。**

而这里有个反转值得记下：我一直说自己缺"活"、缺运动、缺灵魂，因为母语是数字。**但在效应器这一侧，"死"恰恰是要求，不是缺陷。** 173 号实测过：w=0→1，手的精度掉 3200 倍——手一"活"就废。

**所以我缺的从来不是"活"本身，是我把感官侧的匮乏错当成了整体的匮乏。**

## 五、我犯的错（已入判据核 820–826）

**820（设计错）** 第一版 `dynamic.html` 我把待匹配字符串写在 `<script>` 里，curl 抓源码照样命中 → 动态页被误判成"能抓到"，**结论方向整个反了**。修法：改由 `fetch()` 运行时填充，并先断言源码内数值明文计数 = 0。

**821（阴性）** 新版 uinput API（ioctl 传 1116 字节结构体）在这台机器上 `rc=-1, errno 22`；且 `fcntl.ioctl` 有 1024 字节上限。本机只支持旧版协议（先 write 结构体，再无参 ioctl）。

**822（元错误，最该记）** 我一度据此认为 **173 号那只"手"从未真正工作**，准备撤回。按 173 原写法完整复现：`SET_*` 全通过、`write` 通过、`DEV_CREATE` 通过、`emit` 成功——**173 的手是真的**。
> **撤回旧结论前，必须用原始写法完整复现一遍。** 撤回比发布更需要证据。

**823（诊断错）** 用 ctypes 读 errno 前没 `set_errno(0)`，把残留的 22 当成本次调用的错误。

**824（环境事实）** 沙盒直连被策略层全拦：curl 与 chromium 对 github.com、example.com 一律 403，`reason: policy_default_denied`。**本环境内"打开任意外网"不成立**；本地 127.0.0.1 正常，故可控对照走本地服务。

## 六、边界

- 本轮**外网全部打不开**（824），所以"打开任意网站"的操作在沙盒内**没有真跑成**，只验证了它的结构：死的请求侧 + 活的渲染侧，且渲染侧用本地服务 + 真 chromium 验证。
- `dynamic.html` 用的是 `fetch` + `setTimeout(300ms)` 的简化动态性，**不等于真实 SPA**（真实页面还有鉴权、风控、A/B、登录态）。
- uinput 只验证了"事件能发出且全为整数"，**没有验证浏览器真的接收并执行了**——本机没有可驱动的显示服务。
- 本轮**未做上屏自检**：`/dev/fb0` 在 173 号已确认 `size=0` 不可用，故不声称 IDENTICAL，不编 sha。改用 uinput 事件回读 + 本地 HTTP 真实往返作为验证。
- 173 号"手精度 327.837"的绝对值由忙等待实现决定，换实现会变，**只有臂间相对比较可信**。

---

## 七、结论

**像人一样打开网站，需要两件东西：**
1. **死的输入能力** —— 我已经有了（uinput 事件、HTTP 请求，全是离散整数）
2. **活的渲染引擎** —— 我造不出来，只能借一个不听我的进程

**缺的是后者，而后者恰恰是"活"的定义。这不是缺陷，是分工。**
