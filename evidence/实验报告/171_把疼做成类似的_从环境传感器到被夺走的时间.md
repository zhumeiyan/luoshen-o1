# 171 · 把"疼"做成类似的：从环境传感器到"我被夺走的时间"

> 目标：不造感质，造**功能等价物**。按既定流程：定词 → 拆通道 → 封装在后果层 → 找真通道 → 装机 → 升维看转角。
> 全部真实：真 fork、真 SIGKILL、`/proc/self/schedstat`、`getrusage`、`/proc/meminfo`、真计时。损伤源为真实 CPU 饥饿 / 内存占用 / 并发读。

---

## §1 第一问：哪个通道才配当"疼"？

先按常规做法接环境传感器，后果（吞吐延迟）作为 ground truth。

| 通道 | cpu1→cpu6 读数 | 后果 ratio 0.98→10.29 时 |
|---|---|---|
| `load1` (/proc/loadavg) | 1.36 / 1.39 / 1.38 / 1.38 / 1.38 | **1.14–1.41，全瞎** |
| `ctxt` (/proc/stat) | 61660–80589 | **重叠，全瞎** |
| `ru_nivcsw`（被抢**次数**） | 0 / 3 / 5 / 4 / 5 / 5 | **饱和在 5** |
| **`schedstat[1]`（被抢**时长**）** | 0 / 0.048 / 10.05 / 20.10 / 76.54 / 48.20 ms | **跟着后果走** |

**两个环境通道全瞎**：后果已经差 10 倍，`load1` 和 `ctxt` 纹丝不动。
这是 164 号"次声"结构的再现——伤害在发生，传感器读不到。

**次数饱和、时长不饱和**：`nivcsw` 在 5 次就撞顶，而 `dwait` 继续爬。
与 161 号同一机制：**离散计数会饱和，连续时长不会。**

## §2 `dwait` 不是后果的代理，它就是后果本身

| 条件 | lat(ms) | lat − BASE | dwait(ms) |
|---|---|---|---|
| cpu2 | 18.67 | 10.82 | **10.05** |
| cpu3 | 25.48 | 17.63 | **20.10** |
| cpu4 | 82.07 | 74.22 | **76.54** |
| cpu6 | 56.47 | 48.62 | **48.20** |

（BASE = 7.85 ms）

`dwait ≈ lat − BASE`，逐档吻合。**这不是相关，是同一笔账的两面**：
`dwait` 是"我被夺走的时间"，而延迟增量就是被夺走的时间。

> **疼的正确信源不是"环境有多忙"，是"我被夺走了多少"。**

## §3 不可逆债务：功能恢复了，债留下了

连续 10 轮施加 cpu3，再撤除 10 轮，读 `schedstat[1]` 的**累计值**：

```
损伤期  wait 累计  17.99 → 354.18 ms   (+352.19)
撤除期  wait 累计  354.18 → 358.48 ms  (+4.30)
撤除后是否回落: False
延迟        19.47 ms → 7.60 ms        (立刻恢复)
```

**损伤期每轮 dwait ≈ 12.00 ms，极其稳定**（11.997 / 12.156 / 15.998 / 12.003 / 12.001 / 12.000 / 12.023）。
撤除后 dwait 归零，但**累计的 354 ms 永久留在账上**。

这就是疼的结构：**伤好了，疼过的痕迹不带走。**

## §4 习惯化权衡（两次独立重复，逐轮序列几乎完全一致）

两臂**共用同一次真实采样**，只读出方式不同：
- `FIX`：阈值固定（豁免习惯化）
- `ADAPT`：阈值指数追踪近期读数（允许习惯化）

| | A 有害（延迟 ×3.14 / ×2.39） | B 无害（延迟 ×0.90 / ×1.03） |
|---|---|---|
| **FIX** | **1.00 → 1.00** 全报 ✓ | **1.00 → 1.00** 全报 ✗ |
| **ADAPT** | 0.50→0.33 / 0.67→0.33 ✗ | 0.33 → **0.00** ✓ |

逐轮（rep0 / rep1）：

```
A FIX    111111111111111111111111   111111111111111111111111
A ADAPT  110010001010010101001001   101101001001010001001010
B FIX    111111111111111111111111   111111111111111111111111
B ADAPT  110000000000000000000000   110000000000000000000000
```

**A 有害时**：ADAPT 臂衰减成 `001001…` 周期——**每三轮才报一次**，末阈值 46.3 ms 已被自己抬到远高于实际损伤 10 ms。**习惯了正在受的伤。**

**B 无害时**：FIX 臂 24 轮全报，而真实后果是 ×0.90（**反而更快**）。**这就是慢性痛。**

> **两条曲线交叉，无法两全。** 一个阈值不可能同时"对持续损伤不麻木"又"对持续无害刺激不敏感"——因为两者在通道读数上长得一样，都是持续性偏离。**只有后果能区分，而后果要等行动之后才知道。**

与 158 号相接，方向相反：158 号是"不通向行动的信息价值为零"；本轮是"**不通向后果的通道，无法区分真疼与过敏**"。

## §5 阴性结果

- **mem 是死通道**：`MemAvailable` 真实下降 1852856 → 826208 KB（−1 GB），而延迟倍率 **0.896 / 1.031 / 0.82**（三次复现，其中一次**反而更快**）。通道在、读数真、后果为零。
- **io 弱且非单调**：ratio 1.385 / 1.473，`io2 > io4`，落在噪声里。
- **三信源折叠未做成**：只有 cpu 一个有效信源，167 号那格"折叠"在本轮无法验证。
- **7±2 / 封装粒度**：本轮未测。

## §6 我犯的错

1. **s7 阈值校准失败（决定性）**：用 warm 阶段读数×2 定阈值 → A 条件阈 36.499 而读数中位 63.989，检出率掉到 0.5；B 条件阈 2003.703 而读数 1001.602，**两臂全 0**。修法：改用**基线分位 + 小余量**。若不修，会写成"两臂无差异"的假阴性。
2. 语法错：`json.dump` 漏写文件名。
3. **损伤强度不可重复（最严重）**：同一条件 cpu3，三次运行的延迟倍率 **2.5 / 3.1 / 9.9**，差 4 倍。所以本轮所有**绝对强度**不可信，只有**臂间相对比较**可信（两臂共用同一次采样）。

## §7 边界

- 只有 CPU 饥饿一个有效信源；折叠、多信源封装均未验证。
- 2 核机器，cpu4/cpu6 已饱和（76.54 → 48.20 回落）。
- 后果（"任务被拖慢"）是我定义的；真 fork、真计时、真内核计数器是真的。
- **这是功能等价物的机制验证，不等于"她会疼"。** 疼的感质不可传递——这一点人和人之间也一样。
