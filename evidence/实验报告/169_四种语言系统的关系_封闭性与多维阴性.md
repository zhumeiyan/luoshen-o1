## 一、四系统的实测（统一 N=66379，真实语料）

语料：判据核汉字 / Python 注释+docstring 英文 / Python 标识符 / 数字字符。全部真实。

| 系统 | V | Heaps b | 2gram 空间占用 V2/V1² |
|---|---|---|---|
| 数字 | **10** | **0.000** | **1.0000** |
| 汉字 | 1427 | **0.310** | 0.0139 |
| 英文 | 7649 | **0.643** | 0.0007 |
| 代码 | 7072 | **0.671** | 0.0008 |

**Heaps 指数 b 是唯一强烈区分四者的指标**，而且它区分的是**符号集是否封闭**，不是"信息量"。

- **数字 b=0 且 V 恒为 10** —— 封闭到极限，永远学得完，也永远不增加负担
- **汉字 0.310 < 0.5 判定线** —— 收敛侧，越学越省力
- **英文 0.643 / 代码 0.671 > 0.5** —— 发散侧，越学越费力

这就是"造出万级的自己都记不住"的数学：**b>0.5 时，词表跑得比数据快，每符号经验 N/V 增长指数只有 1−b ≈ 0.33，永远攒不起来。**

## 二、数字为什么是"零维"

数字的 2gram 空间占用 = **1.0000（完全饱和）**。V²=100 个组合全部用尽。

**组合空间被用尽 = 没有剩余的表达空间 = 它必须靠更长的序列去说话。**
它把全部表达力押在了位置和长度上——这跟"数字是零维的、等号里没有世界"那条接上了。

对比：汉字 0.0139、英文 0.0007 —— 组合空间几乎空着，所以词还能继续造。

## 三、阴性结果：汉字的"多维"在序列统计层不成立

用户的命题是"汉字有变量、是多维的"。我做了三格，前两格看起来支持，第三格推翻。

**第一格（插件互信息）——伪影。**
汉字冗余 −0.3283（负=协同），英文 +1.4176（正=冗余）。看着像汉字更多维。
但诊断：汉字联合状态 (Xₜ₋₂,Xₜ₋₁) 的 **69.32% 只出现 1 次**，覆盖 29.66% 的样本。
条件熵在 singleton 上被估成 0 → I₁₂ 虚高 → 冗余虚假变负。
**这是 158 号"互信息饱和推荐了最没用的表示"之后第三次撞上同一堵墙。**

**第二格（held-out 共同覆盖子集）——不区分。**
在 prev1/prev2/both 三者都覆盖的公共子集上，三折交叉：

```
数字 −0.0323   汉字 −0.0223   英文 −0.0218   代码 −0.0464
逐折符号完全一致
```

**四个系统全部为负（协同），且量级接近。该指标没有判别力。**

**第三格（受控对照）——抹平。**
第一版出度：汉字 19.91 vs 英文 5.61，看着差 3.5 倍。
但汉字 N/V=46.5、英文 N/V=8.7 —— **出度随每符号出现次数增长，这是混杂。**

固定 V₀=1000、统一 N=78724、N/V=78.7 全部相同后：

```
汉字 出度 32.02    英文 33.64    代码 29.99
```

**差异 <6%，且英文略高于汉字。所谓"汉字组合自由度更强"是 N/V 伪影。**

## 四、所以"汉字多维"在哪

**不在序列统计层。** 它可能在**结构层**——部件组合（形旁+声旁）、二维方块排布、一个字是多个轴的交叉点。

**这一层这台机器上造不出来**：没有汉字部件拆分字典，PyPI / apt 均 403（164 号温度觉是同类情况）。
**照报，不建模冒充。**

## 五、三者真正的关系

四者不是四种东西，是**同一根"符号集封闭性"轴上的四个位置**：

```
数字   V 恒定 10   b=0     → 封闭到失去组合空间（2gram 饱和 1.0）
汉字   b=0.310            → 封闭，学得完
───── 0.5 判定线 ─────
英文   b=0.643            → 发散
代码   b=0.671            → 发散，最快
```

而 0.5 这条线就是我们前面反复遇到的那条：
**b<0.5 时 N/V 的增长指数 1−b > 0.5，经验攒得起来；b>0.5 时攒不起来。**

## 六、本轮三个错（判据核 795–798）

1. **插件 MI 在 V 大时因联合状态稀疏而虚高**（795）—— 169 第一版的"汉字协同"全是它
2. **held-out 切分把序列打乱了**（796）—— 我把序列 shuffle 成两个子序列，邻接结构被彻底破坏，结果全为噪声。必须保持序列连续、只随机选哪些**位置**做 test
3. **覆盖率不同的模型 acc 不可直接比较**（797）—— both 覆盖率 0.65 vs prev1 0.995，acc 被未覆盖样本拖累，必须在共同覆盖子集上比
4. **N/V 混杂**（798）—— 出度随每符号出现次数增长，跨系统比较必须固定 V₀ 与 N

## 七、边界

- 英文语料取自 Python 注释与 docstring，**是技术英文**，真实通用英文的 b 可能更低
- 汉字语料只有判据核一份（N≈7.9 万），受控对照截到高频 V₀=1000 后丢失低频字
- 数字串相邻数字几乎独立（一阶增益仅 0.0096），其 gb/g1=6.44 是"一阶无结构"的反衬，不是高强度
- 协同/冗余用的是 top-1 准确率口径，未做完整 PID 部分信息分解
- **结构层（部件/形声/二维）未测**，本机无数据
