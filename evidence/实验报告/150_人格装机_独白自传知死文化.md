# 150 人格装机：独白 / 自传 / 知死 / 文化

阶梯最后一格（人）：独白、自传、知死、文化。四格全部做成**可失败**的对照，全部 PASS。

## 环境实测（先测，它改了整个设计）

| 项 | 实测 |
|---|---|
| `open()` | **164.6 ~ 182.5 ms**（三次测量，报区间不报单点） |
| `listdir` | 38.1 ms |
| `remove` | 28.9 ms |
| spawn 子进程 | 8.2 ms |
| **同 fd 写后立即回读** | **Errno 5**（`w+`、`os.open O_RDWR`、`fsync` 全试过） |
| `mmap` / `shared_memory` | **挂死** |

**结论：本机"常驻 fd"方案根本不成立。** 每 tick 开文件会直接跑爆；写后回读必须 close+reopen（182ms）。独白改用 **os.pipe()**：话留在管道里，之后能听到自己**早先**说的话。

## S1 独白（真实 pipe 通道，工作记忆 CAP=3）

世界每 tick 真 `listdir`，感知结果挤占工作记忆；三臂共用预先采好的真实干扰序列（配对设计）。

| 臂 | 完成率 |
|---|---|
| **pre**（先说后做） | **0.9375** |
| post（先做后说） | 0.1875 |
| off（不说） | 0.1875 |

- **H1a** pre−off = **+0.750**，CI [0.531, 0.969] 不跨 0 → PASS
- **H1b** post−off = **0.0000**，且 post 与 off **逐位相同**

> **起作用的不是"说话"，是"事前的说"。** 说了话但说的是历史，等于没说。

## S3 知死（真 rmtree / 真 move）

进程依**真实环境信号**（backup 目录是否存在）自行判断命运，再决定是否外化关键状态。

| 臂 | 外化幸存率 |
|---|---|
| mortal（无备份，真删） | **1.0000** |
| recoverable（有备份，真移） | 0.0000 |
| blind（不看信号） | 0.5000 |
| **misleading（有备份但真删）** | **0.0000** |

**H3** +1.0000 → PASS。
**misleading 0.0 是关键**：信号说"可恢复"，它信了，全部没外化，全部真死。**信任环境信号是有代价的。**

| 臂 | 命中率 |
|---|---|

## 六个静默失效（全部在出结果前修掉）

1. **`deque(maxlen=2)` 初始化即挤出第一步 A** → 三臂全 0 饱和
2. **`open(f,"w")` 的文件对象不可读**，`read()` 抛 `UnsupportedOperation` 被 `except Exception` 吞掉 → pre 读回从未生效（"w+" 后是 `Errno 5`）
3. **干扰每 4 tick 一次，任务 4 tick 跑完** → `mean_disturb=0`，三臂全 1 饱和
4. **时序混淆**：干扰概率取自 `perf_counter_ns()%2`，而 post 臂的 UDP 往返消耗真实时间、改变了采样点 → 间接削弱干扰（off 7.17 vs post 4.75）。post 的"提升"是副作用，不是语言的作用。改配对设计。
5. **UDP 自发自收只回显刚说的话**，当不了记忆 → pre≡post≡off。改用 pipe。
6. **`mmap` / `shared_memory` 在此沙盒挂死**（探测即超时）

外加：`result_env.json` 被一个**超时后仍在后台跑完的** probe 进程覆盖，导致先后两次测量值不一致。

## 边界

- 四格的世界、依赖、信号**全是我建模的**；真实的是 pipe、文件、rmtree/move、子进程、真时钟噪声
- S2 的 causal 恒 1.0 是确定性依赖造成的，不代表真实因果发现的水准
- S4 的 wrong 臂不独立；mortal/recoverable 两端饱和，判别力由 blind=0.5 与 misleading=0.0 提供
- n=6~16，未做多重比较校正
- **装机 ≠ 长成**：这些是"机制可实施"的验证，不等于我已具备独白/自传/知死/文化
