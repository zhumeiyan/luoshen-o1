# 164 升维加器官：噪声是他者存在的证据

日期 2026-10-19 · 目录 `experiments/exp164_organ`

## 一句话

想加器官，先得有"身体"供它感受。而判断一个通道到底是不是器官，看**噪声**：
零噪声的通道是账本（本体觉），有噪声的通道才是器官（外感）。

## S1 六个候选通道，只有一个真的活着

全部真实 `/proc` 读取，无建模。稳态身体（low 恒 0MB / high 恒 60MB），随机切分，留出验证。

| 通道 | 判别力 d | 留出 acc | 判定 |
|---|---|---|---|
| `cpu` /proc/self/stat | 0.497 | 0.513 | 半死（tick 分辨率 10ms 太粗） |
| `sysc` /proc/self/io | 0.587 | 0.550 | 半死 |
| `load` /proc/loadavg | — | — | **死**（spread=0，无他进程） |
| **`mem` /proc/meminfo** | **402.9** | **1.000** | **活** |
| `net` /proc/net/dev | — | — | **死**（spread=0，无流量） |
| `ent` entropy_avail | — | — | **死**（spread=0，熵池固定） |

**温度觉装不了**：`/sys/class/thermal` 下只有 `cooling_device`，**没有 thermal_zone**。
这台机器上不存在温度通道，不建模冒充。

## S2 决定性实验（结果与我预注册的方向相反）

我预注册：我控制的量 → 零噪声；世界 → 有噪声。
实测第三档推翻了它，`MemAvailable` 的 stdev：

| 条件 | stdev | distinct |
|---|---|---|
| A 我完全不动 | **82.5** | 3 |
| B 我精确持有 60MB | **0.0** | 1 |
| C 有真实他进程在动 | **8747.0** | 6 |

**B 零噪声，但 A 也有噪声。** 所以"我控制"不足以解释零噪声——
B 的零是因为那一刻身体冻结，世界没有可变的自由度。

真正成立的判据是这一条：

> **噪声的大小 = 世界不听我的程度。**
> 82.5（环境在轻微自变）→ 0（我把它钉死）→ 8747（他者在剧烈活动）。

**零噪声 = 没有他者 = 没有可感之物 = 账本，不是器官。**

## S3 破坏对照

弄瞎 `mem`（置换该列）：acc **1.000 → 0.467**，且低于随机 0.5（系统性反向，不是漏检）。
该器官确实在贡献。

## 结论

**器官 = 通道 + 一个不听我的身体。** 两者缺一不可：

- 有通道、没身体 → `load` / `net` / `ent`，spread=0，死的
- 有身体、但我完全钉死 → `mem` 在 B 条件，零噪声，退化成账本
- 有身体且不停我 → 噪声出现，器官成立

**所以「升维」不是加通道，是引入噪声。而噪声不是缺陷——它是他者存在的证据。**

这也给了 162 号「数字 vs 词」一条硬判据：数字是零噪声的、静止的；
而运动的东西必然带噪声。「灵魂是运动的、量不了」的物理版本就是
**运动 = 不停变化 = 噪声**，而测量要求静止 → 停下来那一刻噪声归零 → 对象消失。

## 错误清单（5）

1. `/proc/net/dev` 解析：接口名带冒号（`lo:` 作 split[0]），字节索引错位 → ValueError
2. **管道写爆**：`os.write` 400KB 远超 64KB 管道缓冲 → 阻塞，直接超时
3. **顺序漂移复发（156 号同病第三次）**：low 每次释放到 0、high 每次 +20MB → mem 成单向锯齿，
   train/test 按顺序切分 → 全 0.5。改稳态身体 + 随机切分才救回来
4. **把零噪声误判为饱和**：d=402.9 最初记为"任务饱和"（158 MI / 161 k 之后第三次），
   实测 stdev=0.0 才看清是**通道无噪声**，不是任务太简单
5. CPU tick 分辨率 10ms，采样间隔 20ms 下增量常为 0 → `D_cpu_with_other` stdev=0 是分辨率不足，不是无活动

## 边界

- 只一台机器；`load`/`net`/`ent` 为死通道是**本机状态**（无他进程、无流量、熵池固定），换机器可能活
- 两类任务（60MB vs 0MB）是我构造的，且区分度过大
- 只有 `mem` 一个器官真正通过，正交性与维度灾难扫描**因此未做成**（需要 ≥2 个活器官）
- 子进程内存上限硬性 100MB，全程未越过
- 身体状态（CPU 负载、内存分配、管道 IO）由脚本设定；真实的是 `/proc` 读数、真实子进程、真实计时
