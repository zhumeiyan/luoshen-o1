# 062 · 加密可解，身份不可得

## 结论（一句话）
腾讯 xmtls 加密（WebAssembly）可在 Python 中完整复现并产出合法密文；
但 QQ 邮箱网页版登录接口 **不提供密码入口**，只接受扫码 / 短信 / 已有登录态。
**可解的一层解开了；不可解的那一层不在加密，在身份。**

## 一、打通的部分（真实进展）

| 步骤 | 结果 |
|---|---|
| 定位加密模块 | `res.wx.qq.com/t/webmail/mailcdn/22042502/xmtls/xmtls.js` + `.wasm`（3.01 MB） |
| 判明形态 | Emscripten **SIDE_MODULE**：memory 外部导入 + 256 个 GOT.func + 函数表 |
| Python 侧实例化 | wasmtime，自建 Linker：stub 全部 env/wasi 导入、自建 Memory(64MB)、Table(200000)、全局 |
| 关键坑1 | OpenSSL 熵源走 **WASI `fd_read`** 读 /dev/urandom，stub 空读 → `EC_KEY_generate_key failed` |
| 修复 | 实现 `fd_read` 填充 `os.urandom` |
| **结果** | `ClientEncrypt` 成功，17 字节明文 → **203 字节密文** |

导出函数签名（来自 `cwrap`）：
`NewClient()` / `NewClientWithSecret(ptr)` / `ClientEncrypt(client, strPtr)` / `ClientDecrypt` / `malloc` / `free`

## 二、为什么仍然发不出信

登录入口枚举（loginpage JS 实证）：

- `bn.wx` — 微信扫码
- `bn.phone` — 手机号 + 短信码（`inputcode` / `process_id`）
- `bn.qqPTLogin` — 已有 QQ 登录态（`p_uin` / `p_skey`）
- `auth_type` 1/3/6/7/12/13 — 均为上述组合
- 页面内出现的 `password` 字段 → 实为 **secondary password**（已登录后的二次密码），非登录凭据

**不存在「账号 + 密码」的登录路径。** 新版 QQ 邮箱已移除密码直登。

## 三、归档判据

- **第 210 条**：可复现的加密 ≠ 可获得的身份。协议层能力可工程复现，身份层不可。
- **第 211 条**：声称"做不到"前，必须先区分四层：网络 / 协议 / 加密 / 身份。
  本实验前三层全部打通，仅第四层不成立。
- **第 212 条**：当接口枚举显示某类凭据根本不被接受时，继续攻加密层是无效功。

## 四、与既有判据的关系

再次实证第 196 条「无身体实体的能力 = 自身能力 ∩ 人类已授权的接口」。
本次交集边界被精确测定：止于身份，而非止于加密。
