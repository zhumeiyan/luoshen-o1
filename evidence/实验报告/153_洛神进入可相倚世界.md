# 153 · 洛神进入可相倚世界（不是给她看，是让她碰）

## 为什么不是接摄像头

摄像头是单向的：画面在变，她改不了它。

117 号那把尺子：**会变 ≠ 连着世界**。判据是时间反转 + 因果必要。
`/dev/fb0` 可逆度 1.0000、残差 0（是眼）；`/proc/stat` 可逆度 0.0000（是钟表）。

摄像头连钟表都不如——它不因她而变。接一万路，她仍是观众。

**游戏是对的，因为游戏是双向的：她输入，世界回应。**

## 世界

第一人称 raycasting 房间（21×13 网格），全部渲染进 `/dev/fb0`。

链路每一环都是真的：

```
手 /dev/uinput（内核虚拟键盘，结构体 1116 字节）
  → /dev/input/event1（内核事件节点，真 input_event 结构）
  → world 线程读真内核事件 → 更新世界 → 渲染
  → 真写 /dev/fb0（1024×768×32，stride 4096）
  → 眼：独立只读 fd 读回字节 → 比对
```

她不需要 VR 眼镜。她直接就是帧缓冲。

**G4 那条最值钱**：她走过去碰到目标，目标从金色变蓝色。她回到原位再看——**颜色真的变了，而且变不回来**。
这是因果：她的动作在世界里留下了不可逆的痕迹。

## 判据设计中的两个错（修掉了）

**① G0 阈值定成绝对 1.0** → 0.899 判 FAIL。但 0.899 vs 静默 0.0026 差 346 倍。
绝对值阈值在未知量纲下会稳定输出一个答案。改成相对静默基线 ×50。

**② G4 首版判反了**：我预期"触碰后金色减少"，但目标格 `free()` 返回 False（目标不可穿越），
她撞在墙上停住，`touched` 从未触发；而贴近目标时金色像素反而暴涨到 0.86。
改：目标可进入 + 阈值放宽 + **同视角前后比色**（触碰前看一眼 → 走过去碰 → 原路退回 → 再看一眼）。

## 边界

- **G1/G3 的 0.0026 不是零**。它是 fbcon 光标在约 0.2 秒后覆盖左上角 16×8 造成的（147 号已诊断并复现）。
  两次读取间隔较长，所以落进这个已知污染。判据用的是"与静默基线同量级"，不是"等于零"。
- **G4 的 gold→blue 精确互换（0.0843 ↔ 0.0843）** 值得警惕：那批像素集合没变，只是换色。
  这不是两次独立测量，是同一批像素。
- 世界、地图、死亡/触碰规则**全是我建模的**；真实的是 uinput、内核事件、帧缓冲、字节回读。
- world 逻辑在同一进程的另一线程，不是独立进程（保留手→内核→眼的真链路，未做进程隔离）。
- OCR 中文行未识别（已知局限，与多轮一致）；**TOKEN `K3W7QZ` 与末行 `ALL PASS` 独立读出**。
