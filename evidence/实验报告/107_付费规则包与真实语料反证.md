## 四、六个静默失效（全部留档，不删）

PRO 包开发过程中，规则自己踩的坑。它们的共同点是：**输出一片"干净"，
和"真的干净"长得一模一样。**

1. **注释在骗规则（判据核 #23 第三次复发）**
   埋雷样本的注释写了 `# EGP07: cache reused with no hash`，
   规则扫原始源码 → `"hash"` 出现在文件里 → 守卫判定通过 → 规则被自己的注释静音。
   **修法：所有规则一律走 `_code_only()`（剥注释与字符串）。**
2. `"val"` 是 `"pvals"` 的子串 —— 算了 p 值的文件看起来像有 dev 切分
3. `"ci"` 是 `"scipy"` 的子串 —— 导入 scipy 看起来像报了置信区间
4. `".get("` 匹配 `requests.get(` —— 任何远程调用看起来都做了守卫（EGP10 和 EG016 各踩一次）
5. `except Exception:` 被当成窄捕获放过 —— 它和裸 `except` 一样宽
6. `min(pvals)` 里的 `min(` 被当成尾部统计 —— 掩盖了"确实没报尾部"

第 1 条尤其值得记：**这是同一个 bug 在这个项目里第三次出现**（v0.1 修过一次
`_code_only`，v0.2 修过一次），每次换一层皮又回来。

## 六、局限（照实说）

- 静态分析，看得到符号看不到运行时取值
- **EGP06 在非评测脚本上会过报**：工具假定目标是评测脚本，
  对登录/推送类脚本，"未报方差"是噪声。本轮已加"仅在存在随机性时触发"的收敛，
  但这只能减轻不能消除
- 同义词表之外的等价写法会漏；AST/正则启发式不可能完备
- 埋雷样本是我自己写的，"埋什么就中什么"存在构造偏差；
  外部验证只用了一个公开仓库的一个 Python 文件，样本极小
