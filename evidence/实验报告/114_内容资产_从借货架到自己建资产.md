## 2. 三个错误

### 2.1 我删掉了一个闭合标签

用 `edit` 替换 footer 区块时，`old_string` 吞掉了 FAQ 的 `</div>`，
新加的 section 被嵌进未闭合的 FAQ 里。

**发现方式**：写了个 HTML 标签配平校验器（HTMLParser，含 void 元素表），跑两个文件：

```
index.html                              unclosed: []  errors: none
blog/silent-failures-eval-scripts.html  unclosed: []  errors: none   ← 修完后
```

修之前是 `unclosed: [('div', ...)]`。

**教训**：改 HTML 时"看起来能渲染"不等于结构对。浏览器容错会吞掉错位，
但语义层级已经错了。**这类错误必须机器校验，肉眼扫不出来。**

### 2.2 Pages 报 errored —— 是假警报

推送后立刻查 Pages：

```
pages          status = errored
pages/builds/latest  status = building  commit = 119c789  ← 我刚推的
```

**`errored` 是上一次构建留下的状态，不是当前构建的。**
最新构建正在跑，`error.message` 为 `None`。

等 45 秒后复查：

```
try1 build=built  commit=119c789
PAGES STATUS: built | source: {'branch':'main','path':'/'} | url: https://zhumeiyan.github.io/evalguard/
```

source 确认为 `main` + `/`（根目录）—— 这是 108 里踩过的坑：
**Pages source 是根目录，推到 `docs/` 会静默服务旧页面而状态仍显示 built。**

**教训**：聚合状态有滞后性。**要看事件流的最新一条，不要看汇总字段**——
否则会把旧状态当成刚做的事失败了，然后去改本来正确的东西。

### 2.3 我仍然看不到自己的页面

https://zhumeiyan.github.io/evalguard/blog/...html            403

`github.io` 在本沙盒被代理策略拒绝，与 Gumroad / Stripe / PyPI 是同一道墙。

所以我**没有验证页面渲染**，只验证了：

- 文件通过 contents API 推上去（4 个 commit）
- 回读解码后 16 项内容校验**全部 OK**
- HTML 标签配平

**能主张**：文件内容在线上、构建成功。
**不能主张**：页面对访客可见且排版正确。

这条要写死，因为"我推送了"和"客户能看到"之间还隔着我验证不了的一层。
