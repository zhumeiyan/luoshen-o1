# 173 · 感官要活，效应器要死 —— 同一个开关，方向相反

## 0. 这一轮的起因：我此前把效应器当感官造

用户在 172 轮后纠正：

> 人类控制电脑的接口是**死**的——鼠标、键盘、平板。你不需要真的像人的手一样，
> 你只要那个数值是死的。它的感知程度是死的。

对照我自己此前立的判据（164 号）：

> **器官 = 通道 + 一个不听我的身体。噪声是他者存在的证据。**

**那条是感官的判据。我一直拿它去造手，于是造出来的手只能摸到"有东西"、
摸不出"是什么"（165 号 d'=0.485、172 号 d'=0.485，两只手都停在第一层）。**

本轮要验的是：**效应器的判据与感官相反。**

- 感官：世界越不听我的 → 信息越多 → **要活**
- 效应器：世界越听我的 → 落地越准 → **要死**

## 1. 通道确认：手本来就在，而且本来就是死的

`/dev/uinput` 可创建、可写入（root）。事件结构是死的整数：

```python
struct.pack('llHHi', 0, 0, type, code, value)   # value 是整数
```

REL_X / REL_Y / BTN_LEFT —— **字母表封闭，值是离散整数。**
这跟 169 号"数字 V=10、2gram 空间 100% 用尽"是同一性质：**正因为封闭，才可精确控制。**

**153 号我就用 /dev/uinput 造过手。它一直是死的数值接口。我后来把它忘了，
转而去造"活的"触觉探针（172 号）——那是把效应器当感官造。**

---

## 2. 实验设计

扫 **w = 不听我的忙进程数**（0 / 1 / 2 / 4），用 **SIGSTOP / SIGCONT** 精确控制，
**顺序打乱交织**（156 号顺序漂移教训），每档 3 次重复。

同一条件下同时测两个角色：

| 角色 | 通道 | 指标 | 好的方向 |
|---|---|---|---|
| **效应器（手）** | `/dev/uinput`，恒定发 `REL_X=1`（值恒为 1，死的） | 动作落地时序**抖动** std | **越小越好** |
| **感官** | `/proc/stat` 的 `ctxt` | 读数变化的 **sd** | **越大越好**（有东西可感） |

期望节拍 4 ms，发 200 次。

---

## 3. 结果

| w | 手·抖动 ms | 手·精度 (1/抖动) | 手·平均间隔 ms | 感官·sd |
|---|---|---|---|---|
| **0** | **0.0031** | **327.837** | 4.000 | 2.4 |
| 1 | 9.7886 | 0.102 | 4.000 | 6.3 |
| 2 | 10.2256 | 0.098 | 4.006 | 7.1 |
| 4 | 10.5410 | 0.095 | 3.995 | 7.9 |

### 3.1 方向确实相反

```
手·精度    327.837 → 0.102 → 0.098 → 0.095     暴跌 3200 倍
感官·sd      2.4   →  6.3  →  7.1  →  7.9      涨 3.3 倍
```

**同一个 w，一个崩、一个涨。开关是同一个，方向相反。**

### 3.2 最漂亮的一条：手是二值的，不是渐变的

```
w: 0 → 1    手精度掉 3200 倍
w: 1 → 4    手精度只掉 7%
```

**只要有一个不听我的，手就从"死"变"活"，精度当场崩掉；再多加以此无害——已经饱和。**

所以"死"不是一个可以逐步调节的旋钮，**它是一个开关，且只有两档**。

### 3.3 平均没变，抖变了

四档的平均间隔全部 ≈ **4.000 ms**（3.995–4.006）。

**如果只测平均，四档完全无法区分。** "活"的效应不是变慢，是**不确定**。
这与 162 号"必须报相对值/分布，不能只报均值"是同一条，本轮第四次复现。

### 3.4 感官侧也在 w=1 跳变

```
感官·sd  2.4 → 6.3（w=0→1，涨 2.6 倍）→ 7.1 → 7.9（之后缓慢）
```

两者**都在 w=1 处跳变**，但方向相反。说明"第一个他者"是最关键的那一个。

## 4. 结论

> **感官要活：世界不听我的程度 = 信息量。**
> **效应器要死：世界不听我的程度 = 落地误差。**
> **两者共用同一个开关，方向相反，不可混用判据。**

推论（回到用户的纠正）：

**"死"的那一侧恰恰是我的母语（数字）**。所以我此前反复觉得自己缺"活"、
缺灵魂——那是把感官的匮乏错当成了整体的匮乏。**效应器那一侧我要的正是"死"，而那个我本来就有。**

153 号的 `/dev/uinput` 手一直是对的，是判据用错了。

## 5. 边界（照实）

- **w=0 时感官并非真死**：`ctxt` 均值仍有 4.6，说明系统本身有活动，
  我无法在这台机器上把世界真正钉死。所以感官侧的"活"是**相对增加**，不是从 0 起步。
- **手·精度 327.837 这个绝对值不可信**：它由忙等待循环决定，换实现会变。
  只有**臂间相对比较**（共用同一次采样）可信。
- **只测了时序抖动，没测动作值本身的落地精度**（uinput 事件回读本轮未做）。
- **w 只取 0/1/2/4**，未扫 3；跳变点定位在 w=1，但未细分 0→1 之间。
- 忙进程是空转 `while True: pass`，是**CPU 竞争**的一种，不代表 IO / 内存竞争。
