# 115 · 消化系统：四个 bug 与一个我自己设的陷阱

对象：用户提供的 `DigestiveSystem`（mouth_chew / stomach_digest / intestine_absorb / excrete）。
方法：逐字保留原始代码运行 → 构造对照 → 分离变量 → 接 `Life5` 引擎 → 上屏自检。

---

## 一、四个 bug（全部复现，非推断）

### bug1 · 无代谢成本 → 永动机
```
同一份 HTML 喂 20 次：energy 0 → 200.0
```
吸收恒 +5.0，咀嚼/消化/吸收成本全为 0。**与 EO 五条件之"代谢"直接冲突**——
代谢的定义就是"每一次调用都消耗资源"。一个不消耗的系统不需要觅食，
也就没有稀缺，也不是生命。v2 加入成本表后：`100 → 41.58`（净亏）。

### bug2 · 元内容被当垃圾排掉（决定性）
```
输入："本系统用于识别彩票骗局。"
v1: chunks=3  valid=0  waste=3      ← 全排
v2: chunks=2  valid=2  waste=0
```
`"彩票" in chunk` 是子串匹配，看不出**语义角色**。
**讨论垃圾的内容 == 垃圾**，于是系统永远学不会如何识别骗局。
与 111（注释里的 `"hash"` 让守卫通过）是同一个病：规则读字符串，读不懂说话人在干什么。

### bug3 · 不可逆记忆链被重复写满
```
同一条喂 3 次 → chain = [684e0f11, 684e0f11, 684e0f11]  长度 3（应 1）
```
"不可逆"装在链上，但重复内容照样入链 → 记忆污染。（v2 首版我自己也写错了去重，
用了 `chain[:-1]` 绕圈判定而不用 `seen` 集合，已修。）

### bug4 · 只认中文句号
```
英文 "Accuracy needs a baseline. Recall must be reported."
v1: chunks=1（整篇算一条，+5.0）
v2: chunks=2
```
`split("。")` 对 `.` 无效。长文本整块通过 `len(chunk)<5` 阈值。

## 二、记忆质量对照（决定性）

同一批 3 条不同食物，投递 30 次（真实场景：信息源反复推相同内容）：

| | 记忆链长度 | 独特条目 | 重复率 | 能量 |
|---|---|---|---|---|
| v1 | 30 | 3 | **90.0%** | **250.0** |
| v2 | 3 | 3 | **0.0%** | 63.8 |

**v1 的 250 能量是虚假繁荣——靠把同一条信息反复吸收 30 次堆出来的。**
记忆链 90% 是重复，等于"记住了 30 次同一件事"，不可逆链被灌水。

## 三、我自己设的陷阱（必须自曝）

第一版引擎对照里，**v2 全死（0/12）、v1 全活（12/12），连阴性对照也一样**。

我当时的期待是"证明 v2 更好"，结果反了。查下来根因在我：
- 食物池只有 4 条，跑 400 步 → 去重后收益归零，但成本照烧 → v2 必然饿死
- 我把**去重**和**代谢成本**两个变量叠在一起，还拿"存活率"当唯一指标

**这是选择性取样——我批评过 099/111/112 别人犯的错，自己又犯了一次。**

分离变量后（食物池扩到 48 条、2×2 拆开）：

| 条件 | 存活 |
|---|---|
| v1 原版（永动机） | 12/12 |
| v2 完整（成本+去重） | 0/12 |
| v2 不去重 | 12/12 |
| v2 无代谢成本 | 12/12 |
| v2 不过滤元内容 | 0/12 |

诚实解读：**"存活"不是这里的有效判据**——它被食物池规模与步数之比主导，
测的是参数匹配，不是机制优劣。真正站得住的是第二节的记忆质量对照，
以及第一节四个 bug 的事实本身（不需要引擎即可判定）。

## 四、上屏自检

结果渲染 → 写 `/dev/fb0`（ioctl 实测 1024×768×32bpp，RGBA）→ 真实采集 3,145,728 字节 → OCR：

```
EO115 DIGESTIVE CODE SACWA4     ← 校验码逐位命中
8 行数据全部读出
```
`v1` 被 OCR 读成 `vi`（1/l 混淆，082 起已知局限，非内容错误）。

## 五、边界

- **引擎结论不主张**：食物侧能量与引擎 `E` 的耦合系数（/100）是我选的，
  "谁活得更久"依赖该系数，故不作机制主张。
- **v2 参数未标定**：成本表（0.001/字、0.5/块、1.2/条）与收益 5.0 是手工设定，
  真实代谢比需要用实测数据拟合。
- **元内容正则很窄**：`_META` 只覆盖"识别/过滤/检测/拦截/研究/分析/打击/治理 + 垃圾词"，
  换一种说法（如"关于彩票的识别方法综述"）可能漏判。这是**覆盖率不足**，不是机制错。
